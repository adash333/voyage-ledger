
## 結果
コードの変更なし。`specs/017-company-mode.md` を既存の会計エンジン（`trade/accounting.mjs`）、セーブ仕様（`specs/016`）、自由経営モード仕様（`specs/014`）と照らして評価した。

### 結論
- 開始B/S（現金500＋船舶500＝借入金700＋資本金300）、減価償却（25枚×20航海＝500）、利息（700×1%＝7）、株式発行（1株1枚を資本金・超過を資本剰余金）の数字はすべて整合しており、方向性は進めてよい。
- ただし「Approved for implementation」とするには、未定の計算式が受入基準に入っている矛盾など 3 点を先に解消する必要がある。

### 進める前に直すべき点（必須）
1. **未定の数式が受入基準に含まれる。** §2・§10 は船の売却価格と借り換え審査を「追加SPECで確定」としているが、§11-4（返済不能・再建フロー）と §11-5（船売却の帳簿処理）はそれを前提にしている。v1.0 は「船売却なし・借り換えなし」と明記し、再建は「現在港で全在庫を売っても足りなければ特別決算（債務不履行）→次航海に進めず初めから」に限定する案。既存モードの `canSpecialClose` と同じ考え方で実装できる。
2. **決算時の処理順序が未定義。** 発行価額（純資産÷株数）やランキングの B/S スナップショットが順序で変わる。案: ①減価償却 ②支払利息（現金不足なら未払利息） ③決算確定＋ランキング記録（スナップショットはここ） ④任意返済・株式発行・配当（各プレビュー→確定） ⑤次航海へ。株式発行・配当は航海途中では不可（途中は利息・償却が未計上で純資産が過大になる）。§10 の「現金不足時に株式発行」はこれと矛盾するので削除か v1.1 へ。
3. **ランキングの範囲。** 「初めから」でリセットされるか（案A: 1プレイ内のみ、確認ダイアログで警告）、端末内で過去の会社も残すか（案B: 過去プレイの全イベントも保存して再実行検証が必要）。v1.0 は案Aを推奨。

### 推奨改善
4. **ゲームバランス。** 最適プレイ（ヴェネツィアでガラス98個→コンスタンティノープルで売却→コショウ100個→バルセロナで売却）の第1航海試算: 売上2,176、売上原価1,290、航海費30、利息7、減価償却25、純利益824、期末現金1,349。借入700は第1航海で返済可能になり、第10航海の期限と利息7枚は学習上ほぼ見えない。金利1%→5%（初回35枚）や航海費10→30の引き上げを検討。易しさ優先で現状維持も可。
5. **配当の単位と創業者の受取。** 「1株あたり◯枚×発行済株式数」と定義し、創業者300株分も会社から出ていくことを明記。創業者の受取配当累計を B/S の外に表示すると「会社のお金と自分のお金は別」が学べる。
6. **未払利息の精算タイミング**（次航海の決算で最優先、利息に利息はつけない）を明記。
7. **小学生向け用語の併記表**を追加（減価償却費「船が古くなった分の費用」、支払利息「借りたお金のレンタル料」、資本剰余金「株を1枚より高く買ってもらった分」、利益剰余金「もうけのうち会社にためてある分」など）。
8. **キャッシュフローの分類を確定**（営業＝売買・航海費・利息、投資＝船の購入、財務＝返済・株式発行・配当）。「減価償却費は現金が出ていかない費用」を明示。
9. **タブ7本は360pxで多い。** 「売買」「船・銀行」「仕訳帳」「決算書」「記録」の5本に統合案。
10. **細かい明記事項。** 初期船は第1航海から償却、途中購入船の航海費は次区間から、在庫は次航海へ引き継ぐ、第10航海後も継続、借入0なら利息仕訳なし、「原則50枚単位」の「原則」を外す（700は50の倍数なので「50未満なら全額」は発生しない）、株式発行の上限（創業者比率50%未満にならない等）の検討、localStorage キー `voyage-company-v1`、保存 state に `mode:"company"` を入れて既存 `parseSave` と区別、英語版は対象外と明記。

### 実装の見通し
- 既存 `trade/accounting.mjs`（イベント再実行型）の設計をそのまま拡張できる。買う/売る/出航に、船購入・決算確定・返済・発行・配当のイベントを追加し、reduce で B/S・ランキングを再計算する形。`map.mjs`・`save.mjs` の方式も流用可。
- 上記 1〜3 を spec に反映すれば §12 の実装順序 1 から着手できる。
